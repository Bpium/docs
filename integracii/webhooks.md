## Принцип работы

Когда наступает одно из событий, Бипиум выбирает подходящие подписки и рассылает сообщения сторонним системам.

### Вебхук-уведомления

Сервер Bpium отправляет запросы подписчикам одновременно и не ждет завершения их работы.

### Вебхук-запросы

Сервер Bpium отправляет запросы подписчикам одновременно и ждет завершения хотя бы одного с ошибкой или завершения всех подписчиков без ошибок.

-  Таймаут ожидания -- 10 секунд.

-  Ответ с ошибкой от первого подписчика сразу возвращается сотруднику.

### Вебхук-действия

Сервер Bpium:

1. Отправляет запросы подписчикам.

2. Ждет завершения всех подписчиков.

3. Объединяет результаты.

4. Возвращает новые значения полей сотруднику.

### Очередь отправки

Бипиум не использует очередь отправки событий.

Если сторонняя система недоступна -- запрос не будет повторен.

### Порядковый номер сообщения

Бипиум отправляет `sequenceId` -- порядковый номер сообщения для конкретного вебхука.

```javascript

    "id": "2",
    "event": "record.before.updated",
    "sequenceId": 84
  },
  "payload": {
    "catalogId": "5",
    "recordId": "199",
    "values": {
      "2": "Текст",
      "3": null,
      "4": ["1"],
      "5": [{ "id": "1", "title": "admin" }],
      "6": "2016-04-01T08:49:15.920Z"
    },
    "prevValues": {}
  },
  "user": {
    "id": "1"
  }
}
```

## Безопасность

Бипиум подписывает запросы алгоритмом HMAC-MD5.

Подпись передается в заголовке:

```http
X-Hook-Signature
```

### Пример PHP

```php
$signature = base64_encode(
    hash_hmac('md5', $body, $secretKey, true)
);
```

### Пример Node.js

```javascript
var crypto = require('crypto');

var hmac = crypto.createHmac('md5', secretKey);

hmac.setEncoding('base64');
hmac.write(body);
hmac.end();

signature = hmac.read();
```
