Бипиум позволяет редактировать и создавать записи не только в своем интерфейсе, но и в виде отдельной формы.

Веб-формы - это отдельно отображаемая запись или каталог с настраиваемыми правилами доступа.

## Виды веб-форм

Всего в Бипиум есть 2 вида веб-форм.

### Веб-форма добавления/изменения записей

![](<../.gitbook/assets/image (101) (1).png> "Веб-форма на добавление записи"){width=1920px height=954px}

Можно настроить отображение на весь экран, передав параметр `&screen=full` в конце адреса.

Пример:\
`http://test.bpium.ru/?action=record-new&catalog=7&screen=full`

![](<../.gitbook/assets/image (102) (1).png> "Веб-форма на добавление записи на весь экран"){width=1920px height=954px}

### Веб-форма просмотра каталога

Веб-форма отображающая определенный каталог

![](<../.gitbook/assets/image (103) (1).png> "Веб-форма просмотра каталога"){width=1916px height=948px}

## Создание веб-форм

Для создания веб-формы, в первую очередь необходимо создать каталог.

Далее, внутри каталога нужно задать название каталога добавить поля, которые будут отображаться для заполняющего.

![](./webforms.png "Создание каталога для Веб-формы"){width=1440px height=816px}

После сохранения ссылку на веб-форму можно получить перейдя в "Доступ к каталогу" в левом верхнем углу, и в открывшемся окне нажав на один из двух видов.

![](./webforms-2.png "Кнопка «Доступ к каталогу»"){width=1439px height=468px}

![](./webforms-3.png "Выбор одной из двух возможных Веб-форм"){width=1440px height=816px}

## Настройка публичного аккаунта

Бипиум принимает запросы только от авторизованных пользователей и перед отображением веб-формы проверяет права доступа к данным. Соответственно, для открытия веб-формы, необходимо иметь аккаунт в системе, для которого будут выставлены нужные привилегии. Если необходима публичная веб-форма, то мы рекомендуем создать один общий аккаунт, через который можно будет просматривать/редактировать данные, отображаемые в веб-форме. Ниже рассмотрим пример создания и настройки такого аккаунта.

### Создание публичного аккаунта

Для создания аккаунта через который будет осуществляться пользователями доступ к форме, необходимо перейти в каталог "Сотрудники" и там создать нового сотрудника введя любое имя для него и почту, к которой вы имеете доступ. На данную почту придет приглашение, после перехода по которому нужно будет придумать пароль для общего аккаунта.

![](./webforms-4.png "Создание публичного аккаунта"){width=1440px height=816px}

### Автоматическая авторизация

Так как форма предоставляет доступ к записям внутри системы, для взаимодействия нужно быть авторизованным в систему. Если мы просто отправим ссылку на веб-форму, то мы попадем на страницу авторизации с формой для ввода логина и пароля. Однако куда проще сделать автоматическую авторизацию через передачу логина и пароля в запросе. Для этого есть 2 варианта.

#### Авторизация через URL

Формат:\
`https://ВАШДОМЕН.bpium.ru/auth/login?login=ЛОГИН&password=ПАРОЛЬ`

Параметры:

-  *ЛОГИН* -- адрес электронной почты для входа в Бипиум

-  *ПАРОЛЬ* -- пароль для входа в Бипиум

-  *ВАШДОМЕН* -- адрес вашего Бипиума

В данном случае логин/пароль указываются в ссылке, соответственно для общего аккаунта они становятся публичными.

#### Авторизация через сценарий

Если вы не хотите показывать логин и пароль от аккаунта, то можно авторизоваться через передачу cookie. Необходимо создать сценарий следующего вида:

![](<../.gitbook/assets/image (122).png> "Написание сценария"){width=1915px height=858px}

Через компонент Веб-запрос нужно сделать любой валидный запрос в вашу систему включив базовую авторизацию и передав в логин и пароль данные от созданного аккаунта.

![](<../.gitbook/assets/image (123).png> "Настройка компонента Веб-запрос"){width=1914px height=866px}

Далее в компоненте "Назначение переменных" нужно в переменную $headers передать ссылку на работу с записью или каталогом и cookie, а в переменную $status - 302.

![](<../.gitbook/assets/image (124).png> "Настройка компонента Назначение переменных"){width=1916px height=867px}

После необходимо создать [внешний запрос ](./../bpium-setup/systemcatalogs/upravlenie/weblisteners)задав ему URL-идентификатор и прикрепив созданный нами сценарий.\
После этого при переходе по ссылке созданного нами внешнего запроса будет открываться нужная форма.

## Доступ к веб-формам

Для настройки отображения только нужных данных необходимо настроить правовой вид. Для этого нужно. чтобы в вашем каталоге было поле, по которому будут фильтроваться записи. Его нужно сделать неизменяемым вручную и заполненными какими-то данными  В нашем примере таким полем будет поле "Дата заявки" со значением "По умолчанию: текущая дата" и сделаем его редактируемым только через API.

![](./webforms-5.png "Настройка поля для фильтрации записей"){width=1440px height=816px}

В первую очередь необходимо настроить привилегии доступа к разделу. Для этого нужно открыть "Доступ к разделу" и явно указать привилегию "Доступ к разрешенным".

![](https://lh7-rt.googleusercontent.com/docsz/AD_4nXfrumDeqnXkLHZ7Bh0RQmZ0ZGigwT3vNrpqQpFLOQDutjE5kDn-_5T7jaugOPIkVI0X8r-qM_xbpW92ndyfgReR7bN6oGIykN1sX7wnczQW_2mw_m4cUz8hCGnynbiMF4vQy6UKTA?key=Fu7IbIY1cGdYI6W_AzmcYw "Настройка привилегии доступа к разделу"){width=1149px height=521px}

Далее необходимо выставить в "Доступ к каталогу" привилегию для общего аккаунта "Доступ к разрешенным". Если в каталоге есть поля, которые не должны быть видимыми для общего аккаунта,  скрываем его в "Право редактировать поле", в нашем случае скрываем поле "Дата заявки".

![](../.gitbook/assets/каталогпросмотрредактирование.png "Настройка привилегии доступа к разделу"){width=1148px height=500px}

:::danger 

**Важно: у вас должны быть настроены права доступа для сотрудников. Если в привилегиях будет стоять "Все сотрудники - "Администрировать", то эта привилегия перебьет выставленную привилегию для нашего общего аккаунта.**

:::

:::info 

Подробнее о настройке правовой политики в статье «[Права](./../bpium-setup/prava/rules)».

:::

### Доступ для просмотра/редактирования

Если вы хотите позволить видеть или изменять любые записи в каталоге, достаточно поменять в "Доступ к каталогу" привилегию общего аккаунта на "Видеть записи" или "Изменять записи" и следующие пункты можно пропустить.

Для настройки доступа к просмотру определенных записей нужно задать в фильтрах вида значение по которому будет видно записи.

![](./webforms-6.png "Создание правового вида"){width=1440px height=816px}

Далее нужно сохранить выбранный вид, выбрав тип "Правовой" и задать название для администратора.

![](<../.gitbook/assets/image (106) (1).png> "Создание правового вида"){width=1154px height=370px}

В открывшемся окне "Общий доступ к виду" выбираем наш общий аккаунт и задаем привилегию "Видеть записи" и  сохраняем.

![](<../.gitbook/assets/image (109) (1).png> "Создание правового вида"){width=1154px height=459px}

Таким образом, при передаче ссылки на веб-форму для просмотра записи или каталога человек увидит ее, если она попадает под выбранный нами фильтр.\
Если же вам нужно, чтобы человек мог еще и изменять записи, то нужно выставить в  "Общий доступ к виду" вместо "Видеть записи" "Изменять записи".

То же самое с созданием записей, достаточно поменять привилегию на "Создание записей".

:::note 

**Важно: Если вы хотите чтобы была возможность изменять или видеть одну единственную запись, учтите, что открывший ссылку будет иметь доступ ко всем записям попадающих под фильтр вида, если откроет каталог вручную.**

:::

### **Создание записей без возможности просмотра предыдущих записей.**

Для того, чтобы дать возможность создавать записи, но ограничить видимость до этого созданных записей, нужно задать фильтр, по которому не будет попадать ни одна запись. В нашем случае это будет фильтр по полю "Дата заявки", выставим "Не задана". Из-за автоматического формирования даты создания при создании записи, ни одна запись не будет отображаться по такому фильтру.

![](./webforms-7.png "Создание правового вида без возможности просмотра предыдущих записей"){width=1440px height=816px}

Сохраняем все как в предыдущих пунктах,  в "Общий доступ к виду" выбираем наш общий аккаунт и задаем привилегию "Создавать записи" и  сохраняем.\
Теперь перешедший по ссылке сможет вносить данные и сохранять данные, однако при переходе в каталог он не увидит никакой информации.

![](<../.gitbook/assets/image (110) (1).png> "Создание новой записи"){width=1597px height=773px}

![](./webforms-8.png "Пустой каталог"){width=1920px height=919px}

## Интеграция веб-формы на сайт

Для размещения формы на сайте вставьте этот код в то место страницы, в котором вы хотите показать форму.

```
<iframe src='https://ВАШДОМЕН.bpium.ru/?action=record-open&catalog=КАТАЛОГ&screen=full&login=ЛОГИН&password=ПАРОЛЬ' width='800' height='600'>
</iframe>
```

Укажите домен, каталог и авторизационные данные. Не забудьте, что код веб-страниц открытый и любой посетитель сможет увидеть ваши авторизационные данные. Поэтому для размещения используйте данные специального пользователя и настройте его права.\
Пример подобной интеграции реализован у нас на сайте по ссылке <https://bpium.ru/demo>.
