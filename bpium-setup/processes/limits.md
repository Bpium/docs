## Список ограничений

:::lab 

Сводный список ограничений. Подробный смысл параметров описан ниже.

:::

### **В облачной версии Bpium**

В облачной версии параметры ограничения заданы фиксировано.

Параметры замедления исполнения:

-  `BPM_STEP_SIZE`: число компонентов в шаге (100 компонентов).

-  `BPM_STEP_TIMEOUT`: ограничение по длительности исполнения шага (15 минут, `900000` мс).

-  `BPM_STEP_MAX_DELAY_ON`: число шагов процесса, при котором достигается максимальная задержка между шагами для замедления исполнения (1000).

-  `BPM_STEP_MAX_DELAY`: максимальная задержка исполнения между шагами (6 секунд, `6000` мс).

Параметры памяти:

-  `BPM_PROCESS_DATA_LIMIT`: максимальный размер входных параметров и переменных процесса (5 Мб, `5242880` байт).

-  `BPM_PROCESS_RESULT_LIMIT`: максимальный размер выходных параметров, сохраняемых в каталог «Процессы» (\~98 Кб, `100000` байт).

-  `BPM_DOWNLOAD_DATA_LIMIT`: максимальный размер загружаемых данных компонентом «веб-запрос» или «генерация файлов» (5 Мб, `5242880` байт).

Параметры одновременного исполнения:

-  `BPM_DOMEN_CONCURENCY_LIMIT`: максимальное число одновременно исполняемых шагов процессов для компании (10).

-  `BPM_DOMEN_CONCURENCY_DURATION`: интервал отложения шагов при превышении лимита (`1000` мс).

### **В серверной версии Bpium**

Задать параметры ограничения выполнения сценариев можно в конфигурационном файле.\
В документации по установке приведён полный список параметров и инструкцию, как их задать.

## **Пояснения к параметрам**

### **Таймаут шага**

Бипиум исполняет процессы частями по 100 компонентов (шаг). Время выполнения шага ограничено. Если время превышено, то шаг процесса прервётся на последнем завершённом компоненте. Эта ситуация считается корректным завершением шага. Следующий шаг начнётся со следующего компонента сценария.

В версии для установки на свой сервер эти параметры настраиваемые:

`BPM_STEP_SIZE` -- количество компонентов в шаге (по умолчанию `1000`).

`BPM_STEP_TIMEOUT` -- ограничение времени выполнения шага (в миллисекундах).\
По умолчанию: `BPM_COMPONENT_TIMEOUT` × `BPM_STEP_SIZE` (`60000000` мс при дефолтных значениях).

### **Замедление исполнения**

Бипиум исполняет процессы частями (шагами по 100 компонентов), каждый шаг -- с небольшой увеличивающейся паузой. Это позволяет отловить зацикленные сценарии и избежать потерь производительности вашей системы. Пауза рассчитывается перед очередным шагом. Перед первым шагом пауза отсутствует.

Пауза между шагами:

-  1-й шаг (100 компонентов): 0 сек.

-  2-й шаг (200 компонентов): \~0,01 сек.

-  5-й шаг (500 компонентов): \~0,04 сек.

-  10-й шаг (1000 компонентов): \~0,09 сек.

-  20-й шаг (2000 компонентов): \~0,17 сек.

-  50-й шаг (5000 компонентов): \~0,4 сек.

-  100-й шаг (10 000 компонентов): \~0,8 сек.

-  200-й шаг (20 000 компонентов): \~1,6 сек.

-  500-й шаг (50 000 компонентов): \~3,4 сек.

-  1000-й шаг (100 000 компонентов): 6 сек.

-  10 000-й шаг (1 000 000 компонентов): 6 сек.

В версии для установки на свой сервер эти параметры настраиваемые:

`BPM_STEP_MAX_DELAY_ON` -- число шагов процесса, при котором достигается «максимальная» пауза (1000 шагов).

`BPM_STEP_MAX_DELAY` -- «максимальная» пауза между шагами (`6000` мс = 6 секунд в облаке; по умолчанию `60000` мс = 1 минута). Пауза конкретного шага рассчитывается по формуле:

`BPM_STEP_MAX_DELAY / 1000 × log10( ШАГ / BPM_STEP_MAX_DELAY_ON + 1 ) / log10(2)`

\{% hint style="warning" %} Формула в версии до 1.5: `BPM_STEP_MAX_DELAY × ( ШАГ / BPM_STEP_MAX_DELAY_ON ) ^ 2`

\{% endhint %}

### **Ограничение длительности процесса**

Бипиум ограничивает время исполнения процесса -- 7 дней. При превышении процесс останавливается с ошибкой и возвратом текущих значений.

В версии для установки на свой сервер этот параметр настраиваемый:

`BPM_PROCESS_TIMEOUT` -- максимальная длительность исполнения процесса (в миллисекундах, по умолчанию `604800000`).

### **Ограничение числа одновременных процессов компании**

Бипиум ограничивает число одновременно исполняемых шагов процессов для компании -- 10. При превышении новые шаги откладываются в очередь на время `BPM_DOMEN_CONCURENCY_DURATION` (`1000` мс).

В версии для установки на свой сервер эти параметры настраиваемые:

`BPM_DOMEN_CONCURENCY_LIMIT` -- максимальное число одновременно выполняемых шагов процессов (по умолчанию не задан -- ограничение отключено).

`BPM_DOMEN_CONCURENCY_DURATION` -- интервал отложения при превышении лимита (в миллисекундах, по умолчанию `100`).

### **Ограничение размера переменных процесса**

Бипиум ограничивает общий размер переменных процесса -- 5 Мб (`5242880` байт). Если размер превышен, процесс останавливается с ошибкой и возвратом текущих значений. Тот же параметр ограничивает размер входных параметров при запуске процесса.

В версии для установки на свой сервер этот параметр настраиваемый:

`BPM_PROCESS_DATA_LIMIT` -- максимальный размер переменных процесса и входных параметров (в байтах, по умолчанию `1048576` -- 1 Мб).
